# Writing Calendar

[English](./README.md) | **简体中文**

Writing Calendar 是一个本地优先的 Obsidian 写作统计插件，用侧栏日历、统计工作台、写作目标、专注计时和数据诊断记录真实的写作活动。

*Writing Calendar is a local-first writing statistics plugin for Obsidian, featuring a sidebar calendar, statistics workbench, writing goals, focus sessions, and data diagnostics.*

当前版本：`0.3.13`  
最低支持 Obsidian：`1.7.2`

## 主要功能

- **侧栏写作日历**：按日期展示写作强度，并提供本月、今日、连续写作和目标摘要。
- **统计工作台**：集中查看月历、年度热力图、每日数据、文件贡献、写作目标和专注统计。
- **多项活动指标**：手动输入、增量、删除量和净增。
- **两种计数口径**：创作字数与正文字符数。
- **统计工作区与写作项目**：可按文件夹、标签、扩展名、文件名、Properties，以及 AND / OR / NOT 高级条件组合筛选。
- **写作目标**：支持每日、每周和每月目标，以及近期进度回顾。
- **可选专注计时**：提供倒计时、暂停、休息、本次输入、净增、实际写作、空闲和离开时间统计。
- **多设备数据结构**：每台设备写入独立账本，同步后按稳定 ID 合并和去重。
- **数据诊断**：将当前分文档统计与已确认的基线比较，帮助发现文件消失、字数减少、新增、改名或移动。
- **中英文界面**：可自动跟随 Obsidian，也可以手动选择简体中文或 English。

## 安装

1. 从最新 GitHub Release 下载 `main.js`、`manifest.json` 和 `styles.css`，或下载完整 Release ZIP。
2. 在仓库的 `.obsidian/plugins/` 下创建 `writing-calendar` 文件夹。
3. 将三个插件文件放入该文件夹。
4. 重启 Obsidian，在 **设置 → 第三方插件** 中启用 Writing Calendar。

插件启用后会打开右侧日历。统计工作台、专注计时和数据诊断也可以通过命令面板或相应设置入口打开。

## 统计口径

Writing Calendar 会把几种写作活动分开记录：

- **手动输入**：键盘和输入法最终提交的内容；粘贴是否计入可在设置中选择。
- **增量**：插件识别到的所有新增内容，包括输入和粘贴。
- **删除量**：被移除的内容。
- **净增**：增量减去删除量，可以为负数。

**创作字数**按可见中日韩文字字符、连续拉丁字母单词和数字段计数，并排除 YAML、代码和 Markdown 标记；**正文字符数**用于观察去除空白后的正文规模。

## 写作范围与项目

Writing Calendar 自己维护统计工作区和命名写作项目，不依赖 Chinese Writing Layout 的规则。

范围可以组合文件夹、标签、扩展名、文件名、Properties 和高级条件；同一文件也可以同时属于多个命名项目。

高级筛选是插件内置的轻量表达式，不需要 Dataview。例如：

```text
folder("正文") AND tag("#小说") AND property("status") != "archived"
```

支持 `AND`、`OR`、`NOT` 和括号，可使用 `folder()`、`tag()`、`extension()`、`filename()` 与 `property()` 组合条件。

统计工作台默认跟随当前选中的统计范围。临时高级筛选可以在当前工作台中替代这个范围，但不会覆盖已经同步的工作区或项目规则。

## 专注计时

番茄钟默认关闭，开启后可以显示在侧栏日历下方或独立侧栏。

专注过程中，插件根据真实文字编辑活动估算实际写作和空闲时间；切出 Obsidian 或窗口不可见的时间单独记为离开时间。

手动结束且不足一分钟的专注默认不保存，也可以在设置中允许记录；自然倒计时结束的专注会自动保存。

## 数据诊断

数据诊断的定位是“发现异常”，不是“自己恢复正文”。

你可以把当前分文档统计设为一个已确认的基线，之后再和当前仓库比较。诊断页可以提示：

- 当前字数比基线减少的文件；
- 已经消失的文件；
- 新出现的文件；
- 改名或移动的文件。

诊断检查不会重写历史账本。如果发现可疑的内容变化，可以再去 Obsidian 自带的文件恢复，或同步工具自己的版本历史中检查和恢复正文。

## 数据、同步与隐私

插件不会上传正文，也不需要账号或网络服务。统计数据默认保存在仓库内的普通目录 `写作日历数据/`：

```text
写作日历数据/
├─ devices/       设备信息
├─ ledgers/       写作活动账本
├─ projects/      统计工作区与写作项目规则
└─ focus/         已完成的专注记录
```

这个目录可以跟随你原本使用的文件同步方式一起同步。每台设备只追加自己的记录，Writing Calendar 会合并已经通过同步到达本机的数据。

正在运行中的番茄只保留在当前设备，不会在设备之间接力。

不要随意删除数据目录：当前文件总量可以重新扫描，但历史写作活动和已经完成的专注记录依赖账本。

## 使用边界

- 写作活动从插件启用后开始记录，不会根据旧文件时间虚构历史数据。
- 没有对应本地编辑事务的外部文件变化可以校准当前总字数，但不会被当作某一天的写作活动。
- 插件不会修改 Markdown 正文，也不会向笔记写入私有标识。
- 文件同步由用户选择的同步方式负责，插件本身不判断云端是否已经完成同步。
