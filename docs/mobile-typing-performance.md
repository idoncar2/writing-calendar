# 移动端输入卡顿排查与修复（2026-09-17）

## 已确认的代码开销

1. 输入法组字开始与结束时调用整篇文档的 `toString()`，再通过 `Array.from` 对全文逐字符比较。短词输入的成本随笔记长度增长。
2. 每次活动记录后的通知可在 80 ms 后触发完整统计重算和 DOM 重建。隐藏标签页、收起的移动端抽屉没有跳过刷新；移动端不可见的状态栏仍可能计算仪表盘。
3. 单文件扫描、索引序列化/压缩保存、同步账本重读可能与下一轮输入同时发生。

这些是源码与回归测试确认的开销，不是手机性能采样得出的唯一故障原因。

## 修复

- 使用 CodeMirror 的不可变 Text 与 ChangeSet 合并输入法编辑，只在最终变化跨度上执行原来的 Unicode 差分；保留候选替换、取消输入、emoji 和多处编辑的计数语义。非输入法事务到来前先结束组字，避免将外部改动归为输入。
- 每次编辑器文档变化（包括尚未提交的组字）记录输入时刻。移动端的自动扫描、保存、通知和同步重读等待至少 750 ms 输入空闲。桌面保持原有延时；用户主动请求的检查和初始化扫描不受此延后机制控制。
- 原始活动事件继续写入账本，专注活动回调继续执行，不为流畅性丢弃写作记录。卸载时继续保存索引。
- 日历、工作台、诊断和专注视图在隐藏时只标记需要刷新，显示/布局恢复时补绘。可见性同时检查 DOM、文档后台状态和移动端左右抽屉的 collapsed 状态。
- 移动端不计算不可用的状态栏统计；隐藏文件列表不重建角标，已存在且数字不变的角标不再删除重建。

## 验证与限制

222 项测试及生产构建通过。新增验证覆盖 20 万字符笔记不执行全文字符串转换、候选取消/emoji、多处编辑与旧差分一致、持续输入期间任务不执行、空闲后任务仅执行一次、桌面时序、卸载取消、折叠抽屉与后台页面。

构建文件按项目部署脚本同步到 `D:/codex/obsidian-test/.obsidian/plugins/writing-calendar/` 并核对哈希。当前 Obsidian CLI 无法连接实例，未完成实机重载；也没有可访问的真实移动端，不能声称手机上已完全消除卡顿。

手机验证建议：升级运行文件后重载插件，在一篇长笔记中连续输入中文、切换候选并取消一次组字；分别收起/展开日历抽屉，检查输入流畅度、停顿后统计更新及输入字数。与关闭插件对照时使用相同笔记和输入法。

## 连续快速输入的进一步优化

按键回调中的新增/删除文本原先各解析两次，现在各解析一次，共享结果生成两套统计，保留逐事件计数语义。时区查询原先每条事件新建 Intl.DateTimeFormat，现在缓存一分钟，到期或时钟回退时刷新；系统切换时区后，事件时区标签最多延迟一分钟更新，本地日期仍逐事件计算。

224 项测试与生产构建通过，新增回归检查重复解析次数以及连续输入、缓存到期、时钟回退时的时区解析次数。此轮没有真实手机性能采样，不能据此认定残余卡顿全部消除。
