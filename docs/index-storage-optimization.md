# 文件索引无损压缩（2026-09-14）

## 目标与约束

- 修复同步、原子替换导致的文件身份误判。
- 保留所有历史事件、fileId、路径、标签、属性和其他索引字段。
- 兼容读取已有未压缩索引；转换在本地完成，不上传数据，不改正文。
- 以约 3.8 万条索引、近 2 万条活动事件的库为验证规模。
- 缩减日常读写的索引文件和临时分配；不承诺压缩后运行内存按同一比例下降。
- 不修改活动账本格式，不清理尚未同步到本机的历史可能引用的旧身份。

## 决策

用户已选择保留历史统计。直接按 90 天或数量上限删除墓碑，会失去标签、属性筛选和旧身份的路径信息，因此不采用。只清除当前账本没有引用的墓碑，也不能保证其他设备稍后同步的事件不受影响。

选择平台内置 gzip 无损压缩大索引，以 Base64 存入 `data.json` 的 `fileIndex` 字段，无第三方依赖。单纯删除 JSON 缩进节省较少；拆分索引与历史归档会增加跨文件一致性与迁移复杂度，暂不采用。

## 格式与转换

- 小于 256 KiB 的索引继续保存为原 `formatVersion: 1`。
- 大索引仅在压缩后更小时使用 `formatVersion: 2`、`encoding: gzip-base64`、`data`。
- 解压内容仍是完整的 v1 索引，包含全部墓碑，无字段裁剪。
- 首次转换前，复制并核对原始 `data.json`，保存在插件目录的 `data.pre-compression.json`；已有不同备份不覆盖，使用编号文件。
- 无压缩 API 的运行环境继续写原格式；无法解压、数据损坏或未知版本时停止加载，不写空索引。
- 备份占用额外磁盘空间，但不被正常索引加载流程读取。

旧插件版本不能读取压缩格式。需要回退时，先停用插件、保留当前数据，使用备份恢复；备份之后的文件身份变化不在旧备份里。同步同一插件数据的设备应一起更新到支持压缩的版本。

## 身份与查询

已索引路径的 `ctime` 改变或 `mtime` 回退不再单独生成新 fileId。明确删除或全量扫描确认路径消失后，同名重建仍获得新身份。插件关闭期间同名文件被替换、但没有观察到删除时，保持原身份；时间戳不能可靠区分此情况与同步改写。

当前文件查询使用当前路径映射，不再扫描全部墓碑；诊断计数一次遍历完成，不再构造并排序全量列表。诊断里的墓碑数量仍表示保留的历史身份数量，不会因压缩而减少。

本地状态保存合并积压请求：同一批请求只保存最新状态，写入期间出现的新修改在本轮结束后再保存一次；写入失败会传回请求方，后续请求可以重试。不会合并或删除活动事件。

设备诊断仅保留每台设备的最新有效活动时间，用于原有“最后活动”显示，不再另存一份与账本等长的时间摘要。原始活动仍完整保留。

## 验证

回归测试覆盖大索引所有字段往返一致、已删除文档按标签和属性筛选、两种计数字段与目标统计一致、旧格式与小索引兼容、损坏格式保护、备份校验、20 次改写与索引重载。

实际主库只读检查：`data.json` 18,450,549 字节，37,871 条快照，其中 36,898 条墓碑；活动账本 8,931,528 字节，共 19,316 个不同 eventId，未发现重复事件或坏行。不能通过“事件去重”显著缩减这份账本。

随后用实现后的编码器检查当时的主库副本：18,451,708 → 3,458,723 字节，减少 81.3%；测试库副本 479,124 → 56,761 字节，减少 88.2%。两份索引解压后逐字段一致，索引诊断一致。主库在使用中，两次测量之间新增了记录。这些大小不包含额外保留的转换前备份，不代表进程内存缩减比例。

## 2026-09-16：活动账本处理优化

- 引擎维护事件 ID 集合。正常顺序到达的唯一事件直接追加；迟到或时钟回退的事件二分定位后插入，保持原来的完整排序顺序。重复 ID 仍走完整合并，沿用原有确定性冲突选择。
- 已去重的引擎事件直接聚合，避免每次仪表盘和目标查询再次对所有事件做 JSON 序列化。公开的普通聚合入口仍负责去重。
- 完整排序为每条事件只计算一次排序键；去重只在遇到冲突时计算规范 JSON。
- 合并输入按迭代器消费，不再先复制全部账本；读取文件时直接累计单个事件数组和重复计数，不保留全部文件的解码数组再展开。
- 未改动账本格式、原始事件文件、同步读取时机或项目筛选规则。当前仍会在同步重载时完整读取账本，没有引入可能漏掉远端改写的文件缓存。

本机合成基准（20,000 条事件，顺序追加 20 条）：完整合并 136.02 → 57.02 ms；20 次追加 2,456.50 → 0.30 ms。两条路径最终事件数组逐项相同。这是一次本机事件处理测量，非界面整体响应或跨设备性能保证。

214 项测试和生产构建通过；测试覆盖顺序追加不重扫历史、迟到事件、重复与冲突事件、整体账本替换、两种计数模式，以及现有聚合和坏行诊断。构建产物同步测试库并校验；当前 CLI 无法连接 Obsidian，需启动测试库后重载插件进行实机检查。
